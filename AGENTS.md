PROJECT RULES

1. Do not change the approved technology stack.
2. Do not modify working functionality unless required.
3. Never create fake buttons or placeholder functionality.
4. Every button must have a real implemented action.
5. Every API call must have a real backend endpoint.
6. Every backend endpoint must be connected to the database when required.
7. Never invent database columns.
8. Never use localStorage for primary application data.
9. Use Supabase PostgreSQL as the source of truth.
10. Never expose Supabase service-role keys in the frontend.
11. Validate all user inputs.
12. Handle loading, success and error states.
13. Do not silently swallow errors.
14. Do not use alert() for application notifications.
15. Use reusable components.
16. Keep frontend, backend and AI modules separated.
17. Before completing a task, test the complete user flow.
18. Do not mark a feature complete if only the UI exists.
19. Do not remove existing functionality without explicit permission.
20. If a requirement is unclear, inspect the existing code before making assumptions.
